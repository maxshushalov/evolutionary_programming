# Лабораторная работа №1

Многомерная оптимизация функции HGBat генетическим алгоритмом.

**Дисциплина:** «Эволюционное программирование и генетические алгоритмы».

**Вариант:** 20. **Размерность:** 7. **Область поиска:** `[-15, 15]^7`.
**Цель:** приближённо найти глобальный минимум и сравнить ГА с Random Search
при одинаковом числе вычислений целевой функции.

Работа находится в `project-1` репозитория `evolutionary_programming`.
Все команды ниже выполняются **из папки `project-1`**.

## Математическая постановка

Для вещественного вектора $x=(x_1,\ldots,x_7)$ минимизируется

$$
f(x)=\sqrt{\left|\left(\sum_{i=1}^{d}x_i^2\right)^2-
\left(\sum_{i=1}^{d}x_i\right)^2\right|}
+\frac{0.5\sum_{i=1}^{d}x_i^2+\sum_{i=1}^{d}x_i}{d}+0.5.
$$

Теоретический минимум: $x^*=(-1,\ldots,-1)$, $f(x^*)=0$.
Эта точка используется только для тестов и анализа результатов; поиск о ней не знает.
Функция также принимает другие непустые одномерные векторы для возможности
настроить размерность; сдаваемые эксперименты строго используют `d=7`.

## Алгоритм и параметры

1. Равномерная инициализация популяции в области поиска.
2. Оценка HGBat: меньшее значение лучше.
3. Турнирная селекция: три разных участника в каждом турнире, минимум побеждает.
   В разных турнирах одна особь может выбираться многократно.
4. Арифметический кроссовер с одним новым `alpha ~ U(0,1)` для каждой пары.
5. Независимая гауссовская мутация координат и `np.clip` по границам.
6. Перенос элиты без изменения и без повторной оценки.
7. Повторение до точного исчерпания бюджета.

| Параметр | Значение |
|---|---:|
| Размер популяции | 100 |
| Размер турнира | 3 |
| Вероятность кроссовера | 0.9 |
| Вероятность мутации каждой координаты | 1/7 |
| Sigma, Config A | 1.5 (5% диапазона) |
| Sigma, Config B и базовая конфигурация | 3.0 (10% диапазона) |
| Число элитных особей | 1 |
| Бюджет каждого запуска | 50 000 оценок |
| Запусков каждого метода | 20, seed 0–19 |

Все параметры задаются в `config/default.json`. A и B строятся из одной
конфигурации заменой только `mutation_sigma`; поле sigma из JSON используется
при непосредственном вызове ГА, а серии A/B используют 5%/10% ширины области.
При изменении размерности вероятность мутации в JSON нужно задавать явно.

Начальные 100 оценок входят в бюджет. Полное поколение требует ещё 99 оценок.
В последнем неполном поколении создаётся столько потомков, сколько осталось
оценок; свободные места занимают лучшие старые особи с сохранёнными оценками.
Поэтому размер популяции всегда равен 100. При стандартных параметрах выполняется
504 полных обновления и одно неполное (4 новых потомка), всего 505 поколений
после инициализации. Random Search также выполняет ровно 50 000 оценок.

Никаких готовых генетических алгоритмов или оптимизаторов в проекте нет.

## Установка

Для повторения используйте Python 3.14 (версия проверенного окружения).
Фактически использованные версии Python и пакетов записываются в `results/summary/experiment_metadata.json`.

```bash
python3 -m venv .venv
```

На macOS / Linux:

```bash
source .venv/bin/activate
```

На Windows (cmd):

```bat
.venv\Scripts\activate
```

Установка зависимостей:

```bash
python -m pip install -r requirements.txt
```

## Один запуск

```bash
python -m src.experiments --single ga_config_a --seed 0
python -m src.experiments --single ga_config_b --seed 0
python -m src.experiments --single random_search --seed 0
```

Каждая команда выполняет один запуск с полным бюджетом. Результат сохраняется
в `results/single/<метод>_seed_<seed>.json`, не перезаписывая итоговые серии.

Для использования ГА из Python:

```python
from pathlib import Path
from src.experiments import load_config
from src.genetic_algorithm import run_genetic_algorithm

config, _ = load_config(Path("config/default.json"))
result = run_genetic_algorithm(config, seed=0)
print(result.best_x, result.best_fitness, result.evaluations)
```

## Все эксперименты

```bash
python -m src.experiments
```

Команда выполняет **60 запусков и 3 000 000 оценок HGBat**, сохраняет реальные
результаты, статистику и графики. Повторный запуск перезаписывает эти артефакты.
Для отдельной конфигурации и каталога результатов:

```bash
python -m src.experiments --config config/default.json --output alternative_run
```

Smoke-тесты используют временный каталог и не заменяют полные результаты.

## Jupyter Notebook

```bash
jupyter notebook notebooks/lab1_analysis.ipynb
```

Выберите **Python 3 (ipykernel)** из активного `.venv` и выполните **Run All**.
Ноутбук находит корень проекта из `project-1`, `notebooks` или корня репозитория.
Он импортирует функции из `src`, читает CSV, показывает сохранённые графики,
лучший вектор и расстояние до теоретического оптимума. ГА в нём не дублируется.
Готовый ноутбук содержит выполненные ячейки для просмотра без запуска экспериментов.

## Проверки

```bash
python -m src.objective

```

Проверяются формула, область поиска, операторы, элитизм, неизменный размер

однофакторность A/B, выборочный std, CSV и PNG.

## Результаты и воспроизводимость

- `results/raw/ga_config_a.csv`, `ga_config_b.csv`, `random_search.csv`:
  seed, результат, бюджет, координаты и число поколений для ГА.
- `results/raw/convergence_ga_config_a.csv`, `convergence_ga_config_b.csv`:
  статистика каждого поколения, общий рекорд и размер популяции.
- `results/summary/statistics.csv`: best, mean, median, **sample std (ddof=1)**, worst.
- `results/summary/experiment_metadata.json`: конфигурации, seed, версии и общий бюджет.
- `results/summary/best_solutions.csv`: лучший вектор каждого метода и расстояние до оптимума.
- `results/summary/verification.md`: фактически выполненные проверки проекта.
- `figures/convergence.png`: средняя траектория и диапазон min–max между запусками.
- `figures/final_comparison.png`: boxplot и точки отдельных запусков.
- `report.md`: отчёт из 25 разделов с фактическими результатами.

Результаты и графики сохраняются в Git. `.venv` и кэши исключены.
Все случайные процессы используют локальный `numpy.random.Generator` с явным
seed. При одинаковых параметрах, seed и окружении результат повторяется.
Между версиями NumPy/платформами побитовое совпадение не гарантируется;
для повторения используйте версии из `requirements.txt` и метаданных.
Двадцать повторов характеризуют разброс, но не доказывают глобальную сходимость.

В выполненной серии средние значения составили **0.316383** (A),
**0.277797** (B) и **27.723106** (Random Search). Лучшее значение —
**0.108752**, Config B, seed 12; точный нулевой минимум не достигнут.
Полная статистика и ограничения выводов приведены в отчёте.
