# Как читать код

Начать с `config.json`, затем открыть `run.py` и функцию `main`. Она выбирает генерацию данных, одиночный запуск, пилот, серию, полный перебор или проверку результатов. Основная цепочка запуска: `save_run` → `run_algorithm` → сохранение JSON.

В `problem.py` сначала прочитать `encode` и `decode`. Особь является словарём:

```text
permutation = [3, 1, 4, 2]
route_lengths = [2, 0, 2]
routes = [[3, 1], [], [4, 2]]
```

Перестановка определяет порядок клиентов, размеры задают границы маршрутов. Склад в перестановку не входит, при расчёте он добавляется в начало и конец каждого маршрута. Пустая машина допустима.

Далее прочитать `evaluate`: по каждому маршруту она накапливает расстояние, время и груз. Если машина приехала раньше окна, она ждёт. Окно ограничивает начало обслуживания. Результат оценки является словарём с расстоянием, допустимостью, суммарным нормированным нарушением и отдельными нарушениями. При `details=True` дополнительно возвращается список маршрутов с моментами прибытия, начала и конца обслуживания.

`fitness_key` задаёт правило сравнения. Сначала допустимость, затем нарушение для недопустимого решения, затем длина. Поэтому короткий, но просроченный маршрут не побеждает допустимый. Функция `validate_solution` проверяет структуру генотипа и применяется в проверках; основные операторы сами сохраняют перестановку и сумму размеров.

В `algorithms.py` прочитать функции в таком порядке:

1. `random_solution` и `geometric_solution`: 2 способа построения общей начальной популяции.
2. `order_crossover`: OX сохраняет участок первого родителя и дополняет его порядком второго без повторения клиентов.
3. `mutate`: обмен, разворот или изменение границы маршрутов.
4. `local_neighbor`: разворот внутри маршрута либо перенос клиента на другую машину.
5. `tournament`: выбирает лучший ключ среди случайно выбранных особей.
6. `run_algorithm`: связывает перечисленные этапы в эволюционный цикл.

Элемент популяции имеет вид `{"solution": особь, "score": оценка}`. Потомок хранится отдельно, исходные списки родителей не изменяются. Элитные элементы можно передавать без копирования, потому что операции изменения всегда создают новые списки.

Внутри `run_algorithm` функция `assess` является единственным местом поискового вызова `evaluate`. Она проверяет остаток бюджета, увеличивает счётчик, запоминает лучший результат и точки истории. Вызов `assess(neighbor, local=True)` считает и неудачные локальные попытки. Уже известная оценка элиты повторно не вычисляется.

Главный цикл читается сверху вниз: элита, отбор родителей, кроссовер, мутация, оценка, возможное локальное улучшение, добавление в новое поколение. Ветка локального поиска является единственным различием методов после общей инициализации. Лучшее решение за весь запуск хранится отдельно, поэтому остановка посреди поколения или локального поиска его не теряет.

Генераторы случайных чисел для инициализации, вариации и локального поиска разделены. Одинаковая начальная популяция в паре методов позволяет сопоставлять результаты при одном seed. Результаты разных seed независимы.

В `run.py` посмотреть `experiments`: в основной серии вызываются те же функции, что в одиночном запуске. В `plots.py` сначала прочитать `summarize`, затем `paired_comparisons` и `representative`. Статистика длины строится только по допустимым результатам, число неудач сохраняется отдельно. `test_lab4.py` содержит прямой независимый расчёт маршрута для проверки основной функции оценки.
